① 五种角色怎么干活 → ② 大改时循环验证 → ③ 一事一窗怎么问。取号另见取号说明。

① 角色大前提（边写边想）

开头声明说明书；做完先问你。只当码农 → 改错、验不清；没点头还接着改 → 返工更贵。

触发词：按角色大前提 · 五种角色先过一遍 · 任务结束复检 · 按 frontend-dev-spec / backend-dev-spec

产品要什么？怎样算完？架构放哪？破坏结构吗？
开发只改哪？禁顺手重构体验信息清不清？（前端）
测试怎么当场验？人自己跑，别信「已经测过」
开头声明 Skill；先方案再改结尾前复检 → 交决策 → 等你指示

② 角色循环验证（专门挑刺 · 命中才跑）

方案后/交付前换顶尖视角；输出必须改/建议改/可接受；你没点头不许擅自改。与「任务结束复检」不同：循环验证命中才跑，复检每次收尾都要。

触发词：角色循环验证 · 再验证 · 循环验证 · 帮我看看有没有问题 · 按顶尖产品经理/接口设计者/前端+UI/测试/安全工程师复审（安全仅改权限·密钥·生产）

场景必跑可跳过
需求新主路径、验收未定、大表筛选、权限范围变纯 bug、文案/规范
接口新接/改 REST只同步 mock
前端UI·交互·空错加载态变了纯 utils、无界面
测试改了用例，或上面已必跑纯文档、你明确跳过
安全权限/门禁/密钥/.env/生产没碰 → 默认不跑

禁止：五连空跑；有「必须改」却不等确认就改代码。

③ 会话与提示词（一事一窗 · 五句话方案）

一件可验收的事 ≈ 一个聊天。浪费多半来自聊太久、空转「继续」。过长时 AI 须先 ⚠️。五句话方案 = 只做·输入·输出·约束·验收；写进聊天用【本轮】骨架。

触发词：一事一窗 · 按五句话方案 · 本轮只做… · 收窄本轮 · 新开聊天 · 不要只回继续 · 会话提示 · 说对说明书 · 用轻量模型答

做不做
一事一窗；验收≤5；开口贴【本轮】；换需求新开窗同窗调研→提交→再扩；「帮我改一下」无边界
续做写清只改哪个文件；点名 Skill（前端 frontend / 接口 backend / 提交 da）只回「继续/好」；「全部规范读完」；永远只念 da-workflow
问答用轻量；多文件再用高端；提交走规定入口闲聊开最贵模型；自己敲 git commit；分支名当任务号
【本轮】只做：…  【仓/路径】…；禁止动：…  【输入】…  【输出】…
【约束】最小 diff  【验收】1.… 2.…（≤5）  【模型】问答轻量 / 多文件 Agent  【Skill】按 frontend|backend|da
【续】仅改 <文件>：…  【不要】扩 scope  【验收】…

卡住≥30 分钟且还会遇到 → 15 分钟写成草稿说明。
