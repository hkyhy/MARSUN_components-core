## ① 角色大前提（边写边想）

**是什么 / 为什么**：写代码前过五种角色；开头声明说明书；做完先问你。只当码农 → 改错、验不清；没点头还接着改 → 返工更贵。

| 角色 | 先问清楚                                   | 角色 | 先问清楚                 |
| ---- | ------------------------------------------ | ---- | ------------------------ |
| 产品 | 要什么？怎样算完？                         | 架构 | 放哪？破坏结构吗？       |
| 开发 | 只改哪？禁止顺手重构                       | 体验 | 信息清不清？（前端重点） |
| 测试 | 怎么当场验？**人自己跑**，别信「已经测过」 |      |                          |

| 阶段   | 该怎样                                                 |
| ------ | ------------------------------------------------------ |
| 开头   | 声明 Skill；先方案再动代码                             |
| 中间   | 不懂先写假设；只改本轮                                 |
| 结尾前 | 复检 → 要你拍板的事 → **等你指示**（「任务结束复检」） |

**触发词**：`按角色大前提` · `五种角色先过一遍` · `任务结束复检` · `按 frontend-dev-spec` / `按 backend-dev-spec`（换对说明书，别永远念 da-workflow）

## ② 角色循环验证（专门停下来挑刺）

**是什么 / 为什么**：方案后或交付前，按「改了啥」换顶尖视角复审；输出 **必须改 / 建议改 / 可接受**；你没点头不许擅自改。五种角色是边写边想；循环验证是专门挑刺。

**触发词**：`角色循环验证` · `再验证` · `循环验证` · `帮我看看有没有问题`  
定向：`按顶尖产品经理复审` · `按顶尖接口设计者复审` · `按顶尖前端+UI 复审` · `按顶尖测试工程师复审` · `按顶尖安全工程师复审`（安全仅改权限/密钥/生产才跑）

| 场景 | 必跑（举例）                             | 可跳过                |
| ---- | ---------------------------------------- | --------------------- |
| 需求 | 新主路径、验收未定、大表筛选、权限范围变 | 纯 bug、只改文案/规范 |
| 接口 | 新接/改 REST                             | 只同步 mock           |
| 前端 | UI·交互·空错加载态变了                   | 纯 utils、无界面      |
| 测试 | 改了用例，或上面已必跑                   | 纯文档、你明确跳过    |
| 安全 | 权限码/门禁/密钥/.env/生产               | **没碰 → 默认不跑**   |

|      | 循环验证                             | 任务结束复检     |
| ---- | ------------------------------------ | ---------------- |
| 何时 | 方案后/交付前（**命中才跑**）        | **每次**收尾前   |
| 禁止 | 五连空跑；有「必须改」却不等确认就改 | 跳过复检直接收尾 |

## ③ 会话与提示词（一事一窗 · 含五句话方案）

**是什么 / 为什么**：一件可验收的事 ≈ 一个聊天；第一句写清只做 / 改哪 / 算完。浪费多半来自聊太久、空转「继续」，不是某一句写砸了。

**五句话方案**：Vibe「先方案后代码」五要素——只做 · 输入 · 输出 · 约束 · 验收。写进聊天 = 下面【本轮】骨架；喊「按五句话方案」让 AI 先帮你填一版也行。

**触发词**：`一事一窗` · `本轮只做…` · `按五句话方案` · `收窄本轮` · `新开聊天做…` · `不要只回继续` · `会话提示` / `窗口是不是太长了` · `只交付不改代码` · `说对说明书` / `只读某某 reference` · `用轻量模型答` / `别开最贵模型`

| 做                                                          | 不做                                       |
| ----------------------------------------------------------- | ------------------------------------------ |
| 一事一窗；验收 ≤5；开口贴【本轮】                           | 同窗调研→提交→再扩；「帮我改一下」无边界   |
| 新需求/新仓/新计划 → 新开窗                                 | 超长窗硬「继续」                           |
| 续做写清只改哪个文件                                        | 只回「继续/好」                            |
| 说对 Skill 名再读（前端 frontend / 接口 backend / 提交 da） | 「全部规范读完再改」；永远只念 da-workflow |
| 问答用轻量；多文件改造再用高端                              | 闲聊开最贵模型                             |
| 提交走规定入口，写任务号                                    | 自己敲 git commit；分支名当任务号          |

```text
【本轮】只做：…
【仓/路径】…；禁止动：…
【输入】…    【输出】…
【约束】最小 diff；不顺手重构
【验收】1.… 2.…（≤5）
【模型】问答用轻量；多文件用 Agent
【Skill】按 frontend-dev-spec | backend-dev-spec | da-workflow

【续】仅改 <文件>：…    【不要】扩 scope    【验收】…
```

卡住 ≥30 分钟且还会遇到 → 15 分钟写成草稿说明。过长/空转时 AI 须先 ⚠️，禁止闷头继续。
