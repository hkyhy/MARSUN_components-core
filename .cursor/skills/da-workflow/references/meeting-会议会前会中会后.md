# 会议规范 · 会前 / 会中 / 会后

> 总控：[../SKILL.md](../SKILL.md)  
> 速查：[开发规范速查 · 会议](../../../../docs/ai-native-研效培训/开发规范速查.md)

团队会议类型多（业务会、需求会、评审会等）。**所有会议**统一按会前 → 会中 → 会后三段执行，目标是：**会上逐点击破、会后文字拉平**。

---

## 1. 会前

- 了解会议**主题、目标、议程**（哪怕 5 分钟）。
- 弄清「这场会要解决什么 / 输出什么」。
- 若有材料提前扫一眼；带着问题进场，避免空听。
- **主讲人约束**：提前准备听众材料（**一页纸大纲即可**），会前分发（纸质或链接），避免会中才发、听众无抓手。

---

## 2. 会中

- 讲者讲完后，按会议类型开展**细点研讨**（需求澄清、方案取舍、验收标准、风险等）。
- 争取把议程上的点**逐个击破**，不留「回头再说」的模糊尾巴。
- **自己的部分**做好会议纪要（决策、待办、负责人、时间）。
- 业务彼此关联：**不是自己的部分也要认真听**，避免后续联调/依赖踩坑。

---

## 3. 会后

- 将自己在会上听取的重要内容（尤其是**任务、依赖、验收**）用**文字**记录、梳理并发出（群/文档/Plane 评论均可）。
- 请相关同事**相互确认**：在文字描述下，理解是否已拉平。
- 有歧义当场（或当日）追问，禁止只留在口头记忆里。

---

## 4. Agent / 协作提示

用户说「整理会议纪要 / 会后拉平 / 会前准备」时：按本文件三段结构输出；待办尽量可映射到 Plane / 钉表任务。
